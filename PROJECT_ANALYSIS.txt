1. WHAT IS THIS PROJECT?
================================================================================

This is a "Crop Disease Detection System". A farmer takes a photo of a plant
leaf using a normal photo gallery app or our own web page. The system looks at
that photo and tells the farmer:

    1. What disease the plant has (or "healthy")
    2. How confident the model is (as a percentage)
    3. What medicine / remedy to use (in English AND Hindi)
    4. It also SPEAKS the answer out loud (Text-to-Speech) so a farmer who
       cannot read English can still use it
    5. It also draws a bar chart of the confidence of every class

It works on 3 crops:
    - Tomato   (10 diseases + healthy)
    - Pepper bell (2 classes)
    - Potato   (3 classes)

Total = 15 real classes. The model file actually has 16 output neurons (a 16th
spare neuron exists because of a folder mistake - explained in section 8).

WHO USES IT:
    Indian farmers. That is why the Hindi voice output and the simple
    "leaf photo -> medicine" flow matters. This is the real motivation.

FLOW OF THE WHOLE SYSTEM:

    Leaf photo (test.JPG)
          |
          v
    [index.html]  <- farmer picks photo in browser, sees preview
          |
          |  HTTP POST (multipart/form-data) to localhost:8000/api/predict
          v
    [main.py : FastAPI server]
          |  reads bytes -> resizes to 224x224 -> scales to 0..1
          |  -> model.predict() -> takes top 3 softmax scores
          |  -> maps index number back to a class NAME using class_names.json
          v
    JSON response  {"results":[{class, confidence, remedy}, ...]}
          |
          v
    [index.html] prints the 3 results as green boxes

    (Separately, predict.py does the same thing from the terminal and
     speaks the answer in Hindi using gTTS)

2. IS DEEP LEARNING ACTUALLY USED? (HONEST ANSWER)
================================================================================

YES. 100% yes. This is a genuine deep learning project, not a "just call an
API" project. Here is the proof I collected by inspecting the saved model file
directly (not guessing):

  a) The model file crop_disease_model.h5 is 11.4 MB and contains 104 real
     weight tensors inside the MobileNetV2 block. A fake/hand-made model would
     not have these.

  b) Total parameters in the model = 2,424,016
        Trainable (learned by you) = 166,032
        Frozen (copied from ImageNet) = 2,257,984

  c) The frozen part is EXACTLY MobileNetV2 (1.00, 224) pretrained on
     ImageNet (1,000,000 images, 1,000 classes). Its output shape is
     (None, 7, 7, 1280) - a 7x7 grid of 1280-dimension feature vectors.

  d) I checked the weight VALUES. They are NOT random initialisation.
     GlorotUniform initialisation would give std ~= 0.02-0.03 and mean ~= 0.
     Actual values in the file:
         Dense(1280->128) kernel : mean = -0.001996, std = 0.060801
         Dense(1280->128) bias   : mean = -0.000688, std = 0.013106
         Dense(128->16)   kernel : mean = -0.018597, std = 0.151586
         Dense(128->16)   bias   : mean = -0.007027, std = 0.037936
     Non-zero means and larger-than-init std prove the weights MOVED during
     training. The model was genuinely trained.

  e) I ran inference on test.JPG. It works and gives a confident, sensible
     answer:
         1. Pepper_bell_bacterial_spot     81.81 %
         2. Pepper_bell_healthy            18.19 %
         3. Tomato_tomato_yellowleaf_curl_virus   0.00 %
     Probabilities sum to exactly 1.0000 (correct for softmax).
     Single-image inference time = 0.62 s on this laptop (CPU, no GPU needed).

WHAT TYPE OF DEEP LEARNING IS IT?
    - Convolutional Neural Network (CNN) - yes
    - Transfer Learning - yes, this is the core technique
    - Multi-class image classification - yes (15/16 classes)
    - Feature Extraction + Frozen Backbone + Trainable Classifier Head - yes
    - NOT object detection, NOT segmentation, NOT NLP, NOT a Transformer

HONEST CAVEAT FOR THE INTERVIEWER:
    Your DEEP LEARNING is 100% real. But your TRAINING is very simple:
    only 5 epochs, no image augmentation, only 166K trainable parameters.
    If an experienced interviewer asks "how did you avoid overfitting?",
    the honest answer is "I used a 20% validation split, dropout, class
    weights and a pretrained backbone, but I did NOT use data augmentation
    and only 5 epochs - and I now know that fine-tuning MobileNetV2 with
    augmentation for 20-25 epochs would give a much better model."
    Saying this out loud makes you look MORE mature, not less.

WHY EACH TECHNOLOGY IS THE RIGHT CHOICE (this is the interview answer)

  TensorFlow / Keras
      -> Industry standard for image CNNs. Huge community. Good docs.
      -> MobileNetV2 is available inside Keras with pretrained ImageNet
         weights, so you do NOT need to download anything separately.

  MobileNetV2 (the CNN) - THE MOST IMPORTANT CHOICE
      -> It is a "lightweight" CNN designed for phones and low-power devices.
      -> Only 2.2 million parameters (vs 25 million for ResNet50, 60 million
         for VGG16).
      -> Because it is small, it trains FAST on a normal laptop CPU and
         runs inference in 0.6 seconds without a GPU.
      -> This is exactly right for a farmer's phone. A VGG16 model would be
         10x bigger, slower, and useless on a low-end Android phone.
      -> Also right for YOU, because you trained it on a laptop, not a GPU rig.

  Transfer Learning (weights='imagenet' + trainable=False)
      -> You do not have millions of labelled leaf images.
      -> ImageNet already taught MobileNetV2 what "edges", "texture",
         "spots", "colour blobs", "leaf shape" look like.
      -> You reuse that knowledge and only learn the last 166K parameters
         that map features -> your 15 crop diseases.
      -> This is called transfer learning. It is THE answer to "how did you
         train a deep learning model with only 20,764 images?"

  FastAPI + Uvicorn
      -> Gives you a real REST API, not just a notebook. Interviewers like
         seeing an API.
      -> FastAPI is async, so it can handle many farmer requests at once.
      -> It auto-generates interactive API documentation at /docs for free.

  Vanilla HTML + Bootstrap + JavaScript fetch()
      -> No React, no npm, no build step. Zero frontend dependencies.
      -> For a demo project this is a GOOD choice - it runs by double-clicking
         a file. Nothing to install, nothing to break.

  gTTS + pyttsx3
      -> Two different TTS engines for two languages.
      -> gTTS needs internet but gives natural-quality Hindi voice.
      -> pyttsx3 is offline but lower quality and macOS/Windows only.
      -> The project supports both via one flag: `language = "hi"` or `"en"`.

  Pillow
      -> Needed for `img.verify()` in check_corrupted.py to detect broken JPEGs.

  hashlib (stdlib) + shutil (stdlib)
      -> Used in move_duplicates.py for MD5 fingerprinting of files.
      -> No extra package needed - shows you know the standard library.

5. THE DEEP LEARNING MODEL - LAYER BY LAYER
================================================================================

EXACT ARCHITECTURE (read from the saved .h5 file, not guessed):

  Sequential model, input shape (None, 224, 224, 3) = RGB images, 224x224.

  +---------------------------------------------------------------+
  | Layer 0: Functional "mobilenetv2_1.00_224"                   |
  |   include_top=False   -> no classifier, output is features   |
  |   weights='imagenet'  -> pretrained, then FROZEN              |
  |   trainable = False    -> (train_model.py line 45)             |
  |   104 internal layers (Conv2D, DepthwiseConv2D, BN, ReLU6)   |
  |   OUTPUT: (None, 7, 7, 1280)                                  |
  |   PARAMETERS: 2,257,984  (all frozen)                         |
  |   This is called the FEATURE EXTRACTOR / BACKBONE.            |
  +---------------------------------------------------------------+
  | Layer 1: GlobalAveragePooling2D()          (line 49)          |
  |   Takes the 7x7x1280 grid and averages each 1280-channel      |
  |   column over the 7x7 spatial positions.                      |
  |   OUTPUT: (None, 1280)                                        |
  |   PARAMETERS: 0                                            |
  |   WHY: hugely reduces parameters. Without it, a Dense layer    |
  |   on 7x7x1280 would need 62720 x 128 = 8 MILLION parameters.   |
  |   With GAP it is only 1280 x 128 = 163,840. Also gives         |
  |   translation invariance - the leaf can be slightly off-centre.|
  +---------------------------------------------------------------+
  | Layer 2: Dense(128, activation='relu')    (line 50)          |
  |   1280 -> 128                                               |
  |   PARAMETERS: 1280*128 + 128 = 164,096                       |
  |   WHY 128: a "bottleneck". Forces the network to compress the |
  |   1280 ImageNet features into 128 numbers that are actually   |
  |   meaningful for DISEASE, not generic ImageNet concepts.      |
  |   Lower param count = less overfitting on 16K images.         |
  |   ReLU = max(0, x), adds non-linearity so it is not just one  |
  |   straight line.                                             |
  +---------------------------------------------------------------+
  | Layer 3: Dropout(0.3)                      (line 51)          |
  |   During training, each of the 128 units is randomly zeroed   |
  |   with 30% probability, every update.                        |
  |   WHY: regularisation. Forces the head to not rely on any     |
  |   single neuron. This is the main anti-overfitting tool here. |
  |   In inference, dropout is DISABLED automatically.            |
  +---------------------------------------------------------------+
  | Layer 4: Dense(16, activation='softmax')  (line 52)           |
  |   128 -> 16                                                  |
  |   PARAMETERS: 128*16 + 16 = 2,064                            |
  |   WHY softmax: converts raw scores into a PROBABILITY         |
  |   DISTRIBUTION. All 16 outputs are between 0 and 1 and they    |
  |   sum to exactly 1. I verified the sum = 1.0000.              |
  |   Number 16 = train_gen.num_classes, NOT hardcoded.           |
  +---------------------------------------------------------------+

  MATH CHECK (I verified this equals the file exactly):
      MobileNetV2 frozen      2,257,984
      Dense(1280->128)           164,096
      Dense(128->16)               2,064
      -------------------------- ---------
      TOTAL                    2,424,016   <- matches count_params()

  TRAINABLE FRACTION: 166,032 / 2,424,016 = 6.85%
      i.e. you only trained 6.85% of the network. That is normal and is
      exactly why transfer learning works so well with small datasets.

HOW BIG IS THE MODEL ON DISK?
      2,424,016 params x 4 bytes (float32) = 9.7 MB of weights.
      File is 11.4 MB (extra = optimiser state saved too).
      On a phone this is a perfectly reasonable download.

INFERENCE SPEED (measured on this MacBook, CPU only):
      1 image   : 0.624 s
      8 images  : 0.678 s   (batching is nearly free for this tiny model)
      The 8x jump in throughput shows batching works - good talking point.

  LINE 2   from tensorflow.keras.preprocessing.image import ImageDataGenerator
  WHY      ImageDataGenerator is the tool that:
             (a) reads images from folders,
             (b) automatically assigns labels from folder names,
             (c) rescales pixel values from 0-255 to 0.0-1.0,
             (d) splits into train/validation.
           Writing this loader by hand would be 80+ lines of code.

  LINE 3   from tensorflow.keras.applications import MobileNetV2
  WHY      Gives you a pretrained CNN. Weights are downloaded automatically
           the first time and cached in ~/.keras/models/.

  LINE 4   from tensorflow.keras import layers, models
  WHY      Shorthand. `layers.Dense(...)` instead of
           `tf.keras.layers.Dense(...)`. Keeps code short.

  LINE 5   import os
  WHY      (Not actually used in this file. Harmless leftover.)

  LINE 10  DATASET_PATH = "dataset"
  WHY      Relative path so the script works no matter where you put the
           folder. Relative = portable.

  LINE 11  IMAGE_SIZE = (224, 224)
  WHY      CRITICAL NUMBER. 224x224 is the EXACT input size MobileNetV2 was
           pretrained at. If you used 128x128 the pretrained filters would
           not match. (Exception: MobileNetV2 accepts other sizes, but 224
           keeps the pretrained statistics valid.) This must match line 44.

  LINE 12  BATCH_SIZE = 32
  WHY      32 images are pushed through the network per gradient update.
           Bigger batch = smoother but slower and needs more RAM. 32 is a
           safe default that fits in almost any laptop's RAM.

  LINE 15  datagen = ImageDataGenerator(rescale=1./255, validation_split=0.2)
  WHY      rescale=1./255   -> pixel 255 becomes 1.0. Neural nets need small
                                inputs; large values cause exploding
                                gradients.
           validation_split=0.2 -> 20% of images held out for validation,
                                 80% for training. This is how you detect
                                 overfitting without touching the test data.
           *** HONEST NOTE: this line does NOT enable any augmentation.
               rotation_range, width_shift_range, zoom_range, horizontal_flip
               are all missing. Section 8 explains why this matters. ***

  LINE 17-22  train_gen = datagen.flow_from_directory(...)
  LINE 17     .flow_from_directory(
  WHY        This single call replaces an entire data pipeline. It:
              - walks dataset/ recursively
              - treats each SUB-FOLDER NAME as a class label
              - collects all .jpg/.jpeg/.png inside
              - resizes every image to target_size=(224,224)
              - encodes labels as integers using ALPHABETICAL order
                (this is why class_names.json is alphabetical!)
              - shuffles by default (shuffle=True is the default)
  LINE 19     target_size=IMAGE_SIZE,
  WHY        All images become 224x224x3 tensors. This creates a STACKABLE
              batch, which is the hard part of image classification.
  LINE 20     batch_size=BATCH_SIZE,
  WHY        Lines 18-22 images per step.
  LINE 21     subset='training'
  WHY        The magic word. Because validation_split=0.2 was set, this call
              hands you the first 80%. Line 39 (`subset='validation'`) hands
              you the last 20% of the SAME images, with NO overlap.

  LINE 23  from sklearn.utils.class_weight import compute_class_weight
  *** WARNING: scikit-learn is NOT installed in your venv. This line will
      crash train_model.py right now. Tested: ModuleNotFoundError. ***

  LINE 24  import numpy as np
  WHY      Needed by compute_class_weight for np.unique().

  LINE 27  labels = train_gen.classes
  WHY      This is an integer array, one entry per training image, giving
           that image's class index. e.g. [0, 0, 5, 5, 5, 7, ...]
           It is exactly the ground-truth answer key.

  LINE 28-32  class_weights = compute_class_weight(class_weight='balanced', ...)
  WHY      THIS IS THE SMARTEST LINE IN THE WHOLE PROJECT.
           Your dataset is very imbalanced:
               Tomato_yellow_leaf_curl_virus : 3,208 images (15.4%)
               Potato_healthy                :   294 images ( 1.4%)
           That is an 11x difference.
           'balanced' automatically gives each class a weight proportional to
           1 / (number of images of that class).
           I computed the actual values:
               Potato_healthy                   (294)  -> weight 4.711
               Tomato_mosaic_virus             (373)  -> weight 3.715
               Tomato_yellow_leaf_curl_virus  (3,209) -> weight 0.431
           So the rare classes get pushed ~11x harder, and the common class
           gets pushed down. The model can no longer just learn "always
           predict the biggest class" and get 15% accuracy for free.
  LINE 33  class_weights = dict(enumerate(class_weights))
  WHY      compute_class_weight returns an ARRAY indexed by sorted class
           number. Keras wants a DICTIONARY {class_index: weight}.
           The cleaner version is
               dict(zip(np.unique(labels), class_weights))
           which is correct even if your label numbers have gaps.
           Here it happens to work because your labels are 0..14 with no gaps.

  LINE 36-41  val_gen = datagen.flow_from_directory(..., subset='validation')
  LINE 39     subset='validation'
  WHY      Reuses the SAME datagen so the validation images get the exact
           same rescaling as the training images. If preprocessing differed
           between train and validation, the val loss would be meaningless.

  LINE 44  base_model = MobileNetV2(input_shape=(224,224,3),
                                   include_top=False, weights='imagenet')
  LINE 44a   input_shape=(224, 224, 3)
  WHY        3 = RGB channels. Must equal IMAGE_SIZE and the serving code.
  LINE 44b   include_top=False
  WHY        CRITICAL. Without this, MobileNetV2 would add its OWN
             classification head trained for 1000 ImageNet classes.
             We do not want that. We want only the FEATURE EXTRACTOR.
             Setting it False gives us the raw 7x7x1280 feature map.
  LINE 44c   weights='imagenet'
  WHY        Download + load the 1.28 GB... no, the 14 MB of pretrained
             weights that Google trained on 1.28 million ImageNet photos.
             This single argument is the whole reason transfer learning is
             possible. Without it you would start from scratch with 20K
             images and get garbage.

  LINE 45  base_model.trainable = False
  WHY      *** THE MOST IMPORTANT LINE IN THE PROJECT ***
           This FREEZES all 2,257,984 pretrained parameters.
           "trainable" in Keras = True means "gradient descent is allowed to
           change this weight". Setting False means the optimizer skips them.
           Consequences:
             - You only train 166,032 parameters instead of 2.42 million.
             - Training is much faster.
             - The pretrained features do not get destroyed by our small
               dataset (a big risk called "catastrophic forgetting").
             - Less overfitting on 16K images.
           The trade-off you mention in the interview: you are NOT adapting
           the low-level filters to leaf textures. A stronger project
           UNFREEZES the last few MobileNetV2 layers and trains at a 100x
           smaller learning rate (fine-tuning).

  LINE 47-53  model = models.Sequential([...])
  WHY      Sequential = a straight stack, layer after layer. Correct choice
           because your network has no skip connections. (ResNet would need
           the functional API.)

  LINE 49  layers.GlobalAveragePooling2D(),
  WHY      Explained in section 5. 7x7x1280 -> 1280.

  LINE 50  layers.Dense(128, activation='relu'),
  WHY      The trainable "brain" on top. 1280 -> 128 features that encode
           "brown concentric rings" (early blight) vs "yellowing at margins"
           (leaf mold). ReLU = Rectified Linear Unit = max(0, x). It keeps
           the network non-linear and lets it learn positive-evidence
           features.
           Relu is used in hidden layers; softmax is used only at the output.

  LINE 51  layers.Dropout(0.3),
  WHY      Regularisation. 30% of the 128 neurons are switched off per
           training step, so the network cannot co-adapt and memorize
           specific neurons. At inference Keras automatically disables it,
           so predictions are deterministic.
           0.3 is a moderate, safe value. Going to 0.5 is also common.

  LINE 52  layers.Dense(train_gen.num_classes, activation='softmax')
  LINE 52a   train_gen.num_classes
  WHY        Derived automatically from the number of folders, NOT hardcoded
             to 16. This is good practice - if you add a disease folder and
             retrain, the output layer grows by itself.
             (In your saved model it resolved to 16, see section 8.)
  LINE 52b   activation='softmax'
  WHY        Turns logits into probabilities that sum to 1. This is what lets
             you show a meaningful "confidence %" to the farmer and what lets
             you take a clean top-3 ranking.

  LINE 55  model.compile(optimizer='adam',
                         loss='categorical_crossentropy',
                         metrics=['accuracy'])
  LINE 55a   optimizer='adam'
  WHY        Adam = Adaptive Moment Estimation. It keeps a running average of
             the gradient and the gradient squared, and divides by the square
             root of the second one. Practical effect: each parameter gets
             its own learning rate, so it converges in far fewer epochs than
             plain SGD. It is the default first choice for CNNs.
             You did NOT set lr=, so you get Adam's default 0.001.
  LINE 55b   loss='categorical_crossentropy'
  WHY        THE CORRECT LOSS FOR MULTI-CLASS SOFTMAX. Softmax outputs a
             distribution over 16 classes; cross-entropy measures how far
             that distribution is from the one-hot truth using
             -log(p_correct_class). Punishes confident wrong answers very
             hard (log goes to -infinity as p -> 0), which is exactly what
             you want: a model must not be confidently wrong about blight.
             Small naming note: 'categorical_crossentropy' is the old name.
             Modern style is 'sparse_categorical_crossentropy' when your
             labels are integers, which they are here. Both end up doing the
             same maths in Keras 3.
  LINE 55c   metrics=['accuracy']
  WHY        Keras prints train/val accuracy each epoch. You need this to
             see overfitting (train acc rising, val acc falling).

  LINE 58-63  model.fit(train_gen, validation_data=val_gen,
                        epochs=5, class_weight=class_weights)
  LINE 58     train_gen
  WHY        train_gen is a GENERATOR. Keras pulls one 32-image batch at a
             time from disk, so 16,606 x 224 x 224 x 3 float32 images never
             sit in RAM at once (that would be ~10 GB). This is why the
             script runs on a laptop.
  LINE 59     validation_data=val_gen
  WHY        After every epoch, Keras runs the 4,158 held-out images and
             reports val_loss / val_accuracy. THIS is how you know you are
             overfitting, and how you would pick the best epoch.
  LINE 60     epochs=5
  WHY        *** WEAKEST HYPER-PARAMETER IN THE PROJECT ***
             5 passes over 16,606 images = only about 2,600 gradient steps.
             The head has 166K parameters. 5 epochs is almost certainly
             UNDER-trained. A normal student project uses 20-30 epochs. It
             probably still works because MobileNetV2's features are so good,
             but you left accuracy on the table.
  LINE 62     class_weight=class_weights
  WHY        Activates the balanced weights computed at line 28. Keras
             multiplies each sample's loss by its class's weight, so errors
             on Potato_healthy count ~11x more than errors on the huge

7. THE 40 INTERVIEW QUESTIONS WITH ANSWERS
================================================================================

Q1.  Tell me about this project in 60 seconds.
A1.  "I built a crop disease detection system for Indian farmers. A farmer
     uploads a photo of a leaf, and the system identifies the disease, shows
     a confidence percentage, gives the remedy in English and Hindi, and
     speaks the answer aloud. I trained a MobileNetV2 CNN using transfer
     learning on 20,764 leaf images across 15 disease classes for tomato,
     pepper and potato. I exposed it as a FastAPI REST endpoint and built a
     plain HTML frontend on top. Inference takes 0.6 seconds on CPU."

Q2.  Why transfer learning and not train from scratch?
A2.  "I only have ~20K images. Training a CNN from scratch would need
     hundreds of thousands and would massively overfit. MobileNetV2 was
     pretrained on 1.28 million ImageNet images, so it already knows edges,
     textures, shapes and colour. I froze its 2.26M parameters and trained
     only a 166K-parameter head on top. That got me a working model without
     a GPU."

Q3.  Why MobileNetV2 specifically? Why not ResNet50 or VGG16?
A3.  "MobileNetV2 has only 2.3M parameters vs 25M for ResNet50 and 60M for
     VGG16. It uses inverted residual blocks and depthwise separable
     convolutions, which cut parameters by roughly 30x for similar accuracy
     on ImageNet. It trained in a few hours on my laptop CPU and infers in
     0.6 seconds. Since my end user is a farmer on a mid-range phone,
     a small model is the correct product decision, not just the cheap one."

Q4.  What does base_model.trainable = False actually do?
A4.  "It sets requires_grad to False on all 2,257,984 pretrained parameters.
     Keras' optimizer skips them during model.fit, so only my 166,032 head
     parameters get updated. It makes training faster and, more importantly,
     it prevents the small dataset from destroying the general-purpose ImageNet
     features - that's catastrophic forgetting. The downside is I am not
     adapting the low-level filters to leaf textures; fine-tuning the last
     few MobileNetV2 blocks at 100x lower learning rate would be my next step."

Q5.  Why GlobalAveragePooling2D instead of Flatten?
A5.  "MobileNetV2 with include_top=False outputs a 7x7x1280 map. Flatten
     would make it 62,720 values, and the next Dense layer would need
     62,720 x 128 = 8 million parameters - 48x more than my whole head, and a
     disaster on 16K images. GlobalAveragePooling2D averages each channel over
     the 7x7 grid and gives 1,280 values, so the Dense layer needs only 163,840
     parameters. It also adds translation invariance, which helps because a
     leaf is rarely centred."

Q6.  Why 224x224?
A6.  "That is the resolution MobileNetV2 was pretrained at. Matching it keeps
     the pretrained filter statistics valid. And critically the value must be
     identical in three places: train_model.py IMAGE_SIZE, main.py line 31
     target_size, and predict.py line 46 target_size. I keep them consistent
     by hand, though in a bigger project I'd factor it into one constant."

Q7.  Why rescale by 1/255?
A7.  "Raw pixels are 0-255. Neural networks work best with small, centred
     inputs - large values cause exploding gradients and saturate the
     activations. Dividing by 255 puts everything in [0.0, 1.0]. The critical
     thing is that the inference code must do the EXACT same thing, because
     any mismatch means the serving input is outside the training
     distribution and accuracy silently collapses."

Q8.  Why softmax and why cross-entropy?
A8.  "This is multi-class single-label classification - a leaf has ONE disease.
     Softmax converts 16 raw scores into 16 probabilities that sum to 1, which
     is exactly the probability distribution the labels represent, and it lets
     me rank them for a top-3 result and show a meaningful percentage.
     Categorical cross-entropy measures the gap between my predicted
     distribution and the one-hot truth, using -log of the probability my
     model gave the correct class. Because log blows up as p approaches 0,
     it punishes confident mistakes heavily - critical here, because a farmer
     must never be confidently told a late-blight leaf is healthy."

Q9.  Why use top-3 predictions instead of just the best one?
A9.  "Two reasons. First, honesty: if blight is 55% and leaf mold is 40%, the
     model is genuinely uncertain and the farmer should know that. Second,
     it's more useful: the runner-up tells the farmer which disease to watch
     for over the next week. I compute it with
     predictions.argsort()[-3:][::-1] - argsort gives indices sorted by value,
     the last three are the largest, and [::-1] puts the best first."

Q10. Your dataset is imbalanced. What did you do?
A10. "Very imbalanced: Tomato yellow leaf curl has 3,208 images but Potato
     healthy has 294 - an 11x gap. Without treatment the model just learns to
     predict the big classes and gets high overall accuracy while failing
     completely on the rare ones. I used compute_class_weight with
     class_weight='balanced', which sets each class's weight proportional to
     1 / class count. Potato healthy got weight 4.71 and yellow leaf curl got
     0.43, an 11x correction, and I passed it into model.fit as class_weight.
     The honest gap: I used overall accuracy as my metric, which is exactly
     the metric that hides imbalance. Macro F1 would be the correct one."

Q11. What is data augmentation and did you use it?
A11. "Augmentation creates new training images by flipping, rotating, zooming
     and shifting the originals, so the model sees more variation than the
     raw photos. I did NOT use it - my ImageDataGenerator has only
     rescale and validation_split, no rotation_range or flip. That's a real
     weakness: leaf photos vary enormously in lighting and orientation, so
     adding rotation_range=20, width_shift_range=0.1, zoom_range=0.1,
     horizontal_flip=True and fill_mode='nearest' would very likely improve
     accuracy. It's the first thing I'd change."

Q12. Why 80/20 split, and why that matters.
A12. "I need a set of images the model never trains on, otherwise the training
     accuracy is meaningless - a model can memorise 20K images perfectly and
     still fail on a new photo. validation_split=0.2 with Keras's
     flow_from_directory does a stratified split, so the 20% validation set
     keeps the same class proportions as training. I never touched the
     validation set during training, and I never had a separate test set,
     which is the honest limitation."

Q13. Why only 5 epochs? Is that enough?
A13. "Honestly, probably not enough - 5 epochs over 16,606 images is only
     about 2,600 gradient steps for 166K parameters, so the model is likely
     under-trained. I chose it because it finished on my laptop without a GPU
     and MobileNetV2's pretrained features are strong enough to give a usable
     result quickly. If I had more time I would train 25-30 epochs with a
     ReduceLROnPlateau callback and EarlyStopping, and save ModelCheckpoint on
     the best validation accuracy."

Q14. What is dropout and why 0.3?
A14. "During each training step, Dropout(0.3) sets 30% of the 128 hidden
     units to zero. So the network can't rely on any particular neuron and has
     to spread the learning across all of them. That's regularisation and it
     is my main defence against overfitting on 16K images. At inference Keras
     automatically disables it, so predictions are deterministic. 0.3 is a
     moderate value; 0.5 is common too, and you tune it against validation
     accuracy."

Q15. Why is it called a "CNN" and what makes it convolutional?
A15. "A convolution slides a small filter over the image. Shared weights
     across positions mean the same edge detector is applied everywhere in
     the picture, which is why CNNs need far fewer parameters than a fully
     connected network on raw pixels and generalise to objects at any
     position. MobileNetV2's big efficiency trick is depthwise separable
     convolution: a depthwise convolution per channel, then a pointwise 1x1
     convolution to mix channels, instead of one full convolution - roughly
     the same accuracy for about a tenth of the compute."

Q16. What is Adam and how does it differ from SGD?
A16. "Adam is Adaptive Moment Estimation. It keeps a running average of the
     gradient (the first moment) and a running average of the gradient squared
     (the second moment), and divides by the square root of the second one.
     The effect is that every parameter gets its own effective learning rate:
     parameters that have had large gradients get a smaller step, and
     parameters that barely move get a larger one. It converges in far fewer
     epochs than vanilla SGD, which matters when you only have a laptop. I
     didn't set lr, so it's Adam's default 0.001."

Q17. Why Adam and loss='categorical_crossentropy' - aren't those mismatched?
A17. "No, this is the standard pairing. Softmax output pairs with categorical
     cross-entropy. If I'd used a sigmoid output with multiple independent
     labels I'd need binary_crossentropy instead. One small naming note: I
     used 'categorical_crossentropy', the legacy name, but my labels are
     integers, so the modern spelling is 'sparse_categorical_crossentropy'.
     In Keras 3 both end up doing the same maths."

Q18. Why save class_names.json and not just hardcode the class list?
A18. "Two reasons. First, correctness: Keras assigns class indices in
     ALPHABETICAL order of folder names, and that mapping is not something I
     want to trust my memory on. Saving train_gen.class_indices means the
     mapping is generated by the same code that built the labels, so they
     cannot disagree. Second, the model outputs numbers, not names - so I flip
     the dictionary with {int(v): k for k, v in class_indices.items()} to go
     from name->index to index->name. The weakness of the separate JSON file is
     that it can get out of sync with the model; a production version saves the
     mapping inside the model."

Q19. What happens if train and inference preprocessing disagree?
A19. "The model still runs and still returns numbers, so there's no crash -
     which is what makes it dangerous. But the input is outside the
     distribution the model was trained on, so accuracy quietly collapses and
     you have no error to debug. This is why rescale=1./255 has to appear in
     train_model.py, main.py and predict.py identically, and why target_size
     must be 224 in all of them. In a bigger project I'd write one
     preprocess() function used by both training and serving."

Q20. Why FastAPI instead of Flask?
A20. "FastAPI is async and type-annotated. The annotations aren't just
     documentation - Pydantic validates every request against them at runtime
     and rejects bad input before it reaches my code. It also gives free
     interactive docs at /docs, which is Swagger UI, generated from the
     signature. For a file-upload endpoint it means I get the UploadFile
     parsing and the async read handled for me."

Q21. Why is the function `async def` and why do I need `await`?
A21. "async def runs my function on the event loop instead of on a worker
     thread, so one slow request doesn't block the others. Because I declared
     it async, reading the upload has to be awaited - file.read() returns a
     coroutine, not bytes. If I had written a normal `def`, FastAPI would run
     it in a thread pool and blocking there is fine."

Q22. What is CORS and why did I need it?
A22. "Browsers apply the same-origin policy: JavaScript on localhost:5500 is
     not allowed to call localhost:8000 unless the server opts in. I added
     CORSMiddleware with allow_origins=['*'], allow_methods and allow_headers,
     which makes the browser accept the cross-origin request. One honest
     caveat I noticed in my own config: I set allow_credentials=True together
     with a wildcard origin, and the CORS spec says not to combine those. It
     works for my plain fetch but I'd fix it to an explicit origin list before
     adding auth."

Q23. How does the image actually travel from the browser to Python?
A23. "Three steps. In JavaScript I create a FormData object and append the
     File, which makes the browser encode the body as
     multipart/form-data with a boundary marker. I pass that FormData as the
     fetch body and deliberately do NOT set a Content-Type header, because the
     browser must add the boundary itself. On the server, FastAPI's
     UploadFile = File(...) annotation tells it to parse that multipart body
     and hand me the file. I then wrap the raw bytes in io.BytesIO so
     load_img can read them as if they were a file on disk, which is how I do
     inference on an upload without ever touching the filesystem."

Q24. Why did I load the model at module level instead of inside the handler?
A24. "Performance. Loading an .h5 deserialises 2.4 million parameters and takes
     seconds. If I did it inside the endpoint, every single request would pay
     that. By putting load_model at module level it happens once when uvicorn
     imports main, and the model stays resident in memory. That's the single
     most important performance decision in the backend, and the same applies
     to loading class_names.json."

Q25. Why does main.py return JSONResponse explicitly instead of a plain dict?
A25. "FastAPI can serialise a plain dict automatically, and returning the dict
     directly would have worked. Using JSONResponse is explicit and it lets
     you set a status code if the prediction is unusable - e.g. returning 400
     for 'that is not a plant image'. Being able to add status codes is the
     real reason to reach for it."

Q26. Explain np.expand_dims(img_array, axis=0).
A26. "load_img and img_to_array give me a 224x224x3 array with no batch
     dimension. Keras was trained on batches, so model.predict needs a 4-D
     tensor of shape (batch, 224, 224, 3). expand_dims with axis=0 inserts a
     new leading axis so one image becomes shape (1,224,224,3). Forget it and
     Keras raises a rank-mismatch error."

Q27. What is TTP and how does gTTS work?
A27. "Text-to-Speech converts text into audio. gTTS - Google Text-to-Speech -
     is an unofficial client for Google's Translate TTS endpoint. You pass
     text and lang, and it returns an MP3 which you save and play. Strengths:
     free, no API key, natural Hindi voice. Weaknesses: it makes a network
     request so it needs internet, it's an undocumented endpoint so it can
     break, and it's unsuitable for offline use. pyttsx3 is the alternative I
     used for English - it drives the OS speech engine, so it's fully offline
     but lower quality and macOS/Windows only. For a real product I'd cache
     the audio."

Q28. Why did I build TTS at all?
A28. "Literacy and language. My target user is an Indian farmer who may not
     read English fluently. Printing 'apply chlorothalonil' is useless to
     someone who can't read it. Speaking the remedy in Hindi makes the
     output usable without any extra hardware, and it works for a user who
     also cannot read Devanagari. It's also why I store a Hindi remedy
     dictionary in parallel with the English one. This is a usability
     decision, not a technical one, and I think it's the strongest part of
     the product."

Q29. How would you deploy this?
A29. "I'd containerise it - the model file, the FastAPI app and a slim
     Python base image, so the 370MB dataset isn't shipped. I'd run Gunicorn
     with Uvicorn workers behind Nginx for TLS, add request timeouts and a
     health-check endpoint, and put TensorFlow behind TensorFlow Serving or
     ONNX Runtime + a runtime like Triton for real throughput. For a mobile
     app I'd convert to TFLite or ONNX, which I can do because MobileNetV2 was
     chosen for its small size - that's the payoff of the architecture
     choice."

Q30. What are the main weaknesses of this project?
A30. "Five, honestly. One, only 5 epochs and no data augmentation, so the
     model is likely under-trained and not robust to lighting and rotation.
     Two, I used overall accuracy instead of macro F1, which is the wrong
     metric for an 11x imbalanced dataset. Three, I kept the frozen backbone,
     so I never adapted the features to leaves. Four, there's a real bug I
     found: the duplicates quarantine folder sits inside dataset/, so Keras
     created a 16th junk class and my model has a useless output neuron.
     Five, the API has a crash I reproduced - numpy float32 is not JSON
     serialisable - plus hardcoded remedy dictionaries that have drifted out
     of sync with the class list."

Q31. The model outputs 16 classes but there are only 15 diseases. Why?
A31. "That's a bug I found while auditing. move_duplicates.py creates
     dataset/duplicates to quarantine duplicate images, and that folder lives
     INSIDE dataset/. Keras's flow_from_directory treats every sub-folder as a
     class, so at training time it found 16 folders and built a 16-neuron
     output layer. It is now empty, so index 15 - the 'duplicates' class - was
     never present in the training labels at all. The right fix is to move the
     quarantine folder OUTSIDE dataset/, or delete it, and retrain."

Q32. How do you know your model actually works?
A32. "Three levels. One, I ran inference on a held-out-looking test image and
     the top two predictions were Pepper bacterial spot at 81.81% and Pepper
     healthy at 18.19%, and the probabilities sum to exactly 1, which
     confirms the softmax is intact. Two, during training Keras reported
     validation loss and accuracy each epoch on the 20% split. Three, at
     this project's maturity what I really need is a confusion matrix and
     per-class precision/recall/F1, which I have not built - and that's the
     honest gap, because aggregate accuracy can hide a class that is
     completely broken."

Q33. How would you improve accuracy?
A33. "In order: add data augmentation - cheapest and usually the biggest win.
     Train 25-30 epochs instead of 5 with EarlyStopping on validation loss.
     Unfreeze the last MobileNetV2 block at 100x lower learning rate for
     fine-tuning. Switch the metric to macro F1 and add per-class reporting so
     I can see which disease is failing. Add BatchNorm before the final
     Dense. And try MobileNetV3 or EfficientNetB0, which are newer and
     stronger for the same size."

Q34. What is catastrophic forgetting and how does freezing prevent it?
A34. "When you fine-tune a large pretrained model on a small, narrow dataset,
     the gradient updates are computed from that narrow data alone, so
     general-purpose features that are not useful for your 15 classes get
     destroyed. Early layers that used to detect generic edges and textures
     become specialised to leaf spots. Freezing the backbone removes those
     weights from the optimizer entirely, so the generic features survive and
     only a small adapter is learned on top. Freezing is the conservative
     extreme; fine-tuning the last few blocks with a small learning rate is
     the middle ground and is usually the best accuracy."

Q35. Why GlobalAveragePooling and not a Flatten - is one really better?
A35. "Flatten is better at accuracy when you have plenty of data because it
     preserves the spatial layout. GAP is better when you have little data,
     which I do. GAP has 1,280 parameters flowing into the Dense layer instead
     of 62,720, so it has 48x fewer parameters, which means far less
     overfitting, and it also gives spatial invariance. ResNet's design is
     evidence for this: ResNet50 in Keras ends with GlobalAveragePooling2D
     rather than Flatten. For a 16K-image dataset, GAP is the right call."

Q36. Explain the difference between argmax and argsort.
A36. "argmax returns the INDEX of the single largest value - one index.
     argsort returns ALL the indices, ordered by their values. So argmax gives
     me the top-1 prediction and argsort gives me a ranking, which is what I
     need for the top-3 display. To get the top-3 indices I do
     argsort()[-3:], taking the last three of the sorted list, and then
     [::-1] to reverse so the best is first."

Q37. What is MD5 and why is it valid for finding duplicate images?
A37. "MD5 is a hash function: it takes any input and returns a fixed
     128-bit value, and it has the property that identical inputs always give
     identical outputs. So I hash every file's bytes and if two hashes match,
     the files must have identical content, so they are duplicates. The
     limitation is important and I would state it in an interview: MD5 only
     catches BYTE-identical files. The same leaf photographed at a slightly
     different angle has completely different bytes and a different hash, so
     it is missed. Also, my scan found 411 files with .1/.2 suffixes that are
     probably re-shoots of the same leaf, so near-duplicate leakage between
     train and validation is a real risk here."

Q38. How does Img.verify() detect a corrupted JPEG?
A39.  "A JPEG is structured as a start-of-image marker, then compressed scan
     data, then an end-of-image marker. If a download was interrupted, the
     file can have a valid header and truncated or corrupt scan data.
     PIL's Image.open() is lazy - it reads only the header, so it succeeds even
     on a broken file. Image.verify() then walks the data blocks and raises if
     the structure does not hold up. This matters practically: one corrupt
     file inside a training batch crashes model.fit() hours in, with an error
     that does not obviously point at the file. I also found a genuine bug in
     my own checker - it pointed at the absolute path '/dataset' which does
     not exist, so it was walking nothing and reporting zero corrupted images.
     A script that silently checks nothing is worse than no script."

Q39. Why store model weights as .h5 and not as .ckpt or pickle?
A39.  ".h5 is HDF5 and it stores the model ARCHITECTURE plus the weights plus
     the optimizer state in one self-describing file. That means serving code
     only needs tf.keras.models.load_model('crop_disease_model.h5') and does
     not have to rebuild the architecture - that is why main.py is so short.
     A bare TensorFlow checkpoint would require rebuilding the model graph in
     code and would silently break if I changed the architecture.
     The modern preference is the .keras format or SavedModel, which are more
     robust, and TFLite or ONNX if I need to run on a phone."

Q40. If I had to rebuild this today, what would be different?
A40.  "Put the preprocessing in one shared function used by training and
     serving so they cannot drift. Save the class mapping inside the model.
     Add data augmentation and train 25+ epochs with EarlyStopping. Report
     macro F1 and a confusion matrix. Fix the numpy-float JSON crash. Move the
     duplicates folder out of dataset/ and retrain so the model has 15 clean
     outputs. Load remedies from a single JSON with per-language fields instead
     of two Python dicts. And convert to TFLite so it runs offline on the
     farmer's phone - which is the entire point of choosing MobileNetV2."

13. ONE-LINE ANSWERS YOU MUST MEMORISE
================================================================================

  Q: What does the model output?
  A: A vector of 16 softmax probabilities that sum to 1, one per class. I take
     the top 3 with argsort and map the indices back to names using
     class_names.json.

  Q: What is transfer learning and why did you use it?
  A: Reusing a network pretrained on a huge dataset (ImageNet) for a new small
     dataset. I had 16K training images, which is far too few to train a CNN
     from scratch. Freezing the pretrained 2.26M parameters and training only
     a 166K head gave me a working model on a laptop with no GPU.

  Q: How big is the model and how fast is it?
  A: 2,424,016 parameters, 11.4 MB on disk, 0.62 seconds for a single image
     on CPU. MobileNetV2 was chosen specifically so it is small enough to run
     on a phone.

  Q: What is your train/validation split?
  A: 80/20 stratified, done inside Keras with validation_split=0.2 and
     subset='training' / subset='validation'. 16,606 training images and
     4,158 validation images, with no overlap between them.

  Q: What optimizer and loss did you use, and why?
  A: Adam with categorical cross-entropy. Adam gives each parameter its own
     effective learning rate so it converges fast without a GPU.
     Categorical cross-entropy is the correct pairing with softmax for a
     single-label multi-class problem, and it punishes confident wrong
     predictions very hard - which matters because a farmer must never be
     confidently told a diseased leaf is healthy.

  Q: What is the single biggest thing I would improve?
  A: Data augmentation and more epochs. My ImageDataGenerator only rescales;
     it never rotates or flips anything. Adding rotation, shift, zoom and
     flip, and training 30 epochs with EarlyStopping instead of 5, would very
     likely be my biggest accuracy win - and it costs no new data.

  Q: Why FastAPI?
  A: It gives me a real REST API with automatic input validation from type
     annotations, async concurrency for handling many uploads, and free
     interactive documentation at /docs.

  Q: Why do you load the model outside the request handler?
  A: Performance. load_model takes seconds because it deserialises 2.4M
     parameters. At module level it happens once at startup, so every request
     just reuses the warm model.

  Q: What is the single biggest bug you found in your own project?
  A: My API was returning HTTP 500 on every request. The model predicted fine,
     but round() on a numpy.float32 returns a numpy.float32, and Python's
     json.dumps cannot serialise it. The fix was one character:
     round(float(100 * x), 2). I found it by calling my own endpoint with curl
     instead of trusting the frontend.


================================================================================
14. INTERVIEWER'S LIKELY TRICKY QUESTIONS
================================================================================

  "Your model has 16 outputs but you said 15 diseases. Explain."
      -> The duplicates quarantine folder is a sub-folder of dataset/, and
         flow_from_directory treats every sub-folder as a class. It is empty
         now, so index 15 never appeared in training. I would move it outside
         dataset/ and retrain.

  "How do you know you are not overfitting?"
      -> I would compare training accuracy to validation accuracy per epoch. If
         train keeps rising while val falls, I am overfitting. Right now I
         cannot answer this properly because I only trained 5 epochs and did
         not save a history. My plan is to add EarlyStopping on val_loss,
         restore_best_weights, and augmentation. That is the honest answer.

  "Your dataset has 3,209 images of one class and 294 of another. What is your
   accuracy actually telling you?"
      -> Overall accuracy is the wrong metric here. A model that predicted
         "yellow leaf curl" every single time would get 15% accuracy while
         completely failing on every rare disease. I should be reporting macro
         F1, which weights every class equally, plus a per-class breakdown. I
         used class weights to reduce the problem during training, but I am
         aware that my metric is still the wrong one.

  "What if a farmer uploads a photo of a car?"
      -> Honesty: my model has no out-of-distribution detection. It will return
         a confident answer for one of my 15 classes no matter what. A real
         system needs a rejection step - either a confidence threshold that
         says "I am not sure, retake the photo", or an out-of-distribution
         layer comparing the input embedding against the training set
         distribution. I would add a threshold below, say, 60% confidence.

  "Why not use a bigger model if the dataset is 20K images?"
      -> Accuracy per unit of cost. MobileNetV2 gives me 2.4M parameters,
         0.6s CPU inference and an 11MB download. ResNet50 would be ~10x
         bigger and slower for maybe 1-2% more accuracy. My user is on a
         low-end Android phone in a field with patchy connectivity, so a
         smaller model is the right product call. If I had a labelled test set
         I could measure whether the accuracy was worth it.

  "How would you know if your model works on real farmers' photos and not just
   this dataset?"
      -> This dataset is from a clean, controlled research collection. Real
         photos will have soil in the background, motion blur, bad lighting,
     different phone cameras and the leaf partly out of frame. The honest
     test is to collect real field photos, treat them as a separate test set
     I never trained on, and measure accuracy and macro F1 on them. I would
     also report per-disease accuracy, because diseases like early blight
     and septoria leaf spot look very similar and will be my worst classes.

  "What is the difference between your train_model.py preprocessing and your
   main.py preprocessing, and how do you guarantee they match?"
      -> They are currently duplicated in three places and kept in sync by
     hand, which is fragile. The real answer is a single shared
     preprocess() function - or, better, saving the preprocessing config
     inside the model and having the serving code read it, so the model and
     its preprocessing can never disagree.

  "If you had one more week, what would you do?"
      -> In order: fix the JSON serialisation bug so the app works; add data
     augmentation and train 30 epochs with EarlyStopping; build a confusion
     matrix and per-class F1 report and put it in the README; move remedies
     into a single JSON and add the missing Tomato_late_blight entry; delete
     the junk duplicates class and retrain cleanly; add a requirements.txt;
     and convert the model to TFLite so it runs offline on a phone. That last
     one is the payoff of choosing MobileNetV2 in the first place.
